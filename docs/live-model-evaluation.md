# 실제 모델 평가와 개선 실험

2026-08-31, 공개 저장소의 합성 자료로 OpenAI 모델을 직접 호출했습니다. 최종적으로 **Sol과 `tax-memo.v1.4.0` 조합을 코드 기본값으로 채택**했습니다. 기존 개발 질문 8개와 수정 전에 고정한 별도 질문 12개를 각각 2회 실행해 총 40/40건이 응답 계약을 통과했습니다. 이는 세무 정확도나 실사용 준비 완료를 뜻하지 않습니다.

첫 후보 `tax-memo.v1.3.2-candidate`는 질문과 무관한 답변을 생성해 채택하지 않았습니다. [초기 130회 원시 결과](../artifacts/portfolio/live-evaluation-report.json)와 [추가 80회 결과](../artifacts/portfolio/live-release-report.json)에 성공과 실패를 모두 보존했습니다. 공개 데모는 결정론적 AI 흐름을 유지하며 유료 모델을 호출하지 않습니다.

## 최종 보완과 별도 질문 검증

추가 변경은 프롬프트 지시만 강화하는 데 그치지 않고 도구 간 입력 계약을 바꿨습니다.

1. **원래 질문으로 검색:** 모델이 검색어를 바꿔 다른 주제로 이동할 수 없게 했습니다. 주장 검사에서도 같은 질문으로 승인 상태와 최신 근거를 다시 확인합니다.
2. **질문 관련성 검증:** 독립 검증 모델에 원래 질문을 전달합니다. 주장 자체가 원문에 맞아도 질문의 세목과 확인 항목을 모두 다루지 않으면 전달을 거부합니다. `SUPPORTED` 판정만으로 이 조건을 우회할 수 없습니다.
3. **검증본의 서버 보관:** 독립 검증 입력은 서버가 보관한 주장으로 구성합니다. 최종 도구는 빈 객체만 받고, 서버의 검증본을 그대로 전달하거나 저장합니다. 질문, 본문, 근거와 계산 결과의 산출물 해시도 다시 확인합니다.
4. **실패의 명시적 종료:** 전달 도구의 호출 자체를 성공으로 취급하지 않습니다. 도구 오류가 나면 답변 보류로 마무리하고 읽기 전용 실행의 검토조서 저장도 거부합니다.

검증 책임은 [독립 검증 도구](../src/lib/ai/agents/evidence-verifier.ts), 실행 순서는 [에이전트](../src/lib/ai/agents/tax-agent.ts), 산출물 무결성은 [세무 도구](../src/lib/ai/tools.ts)로 분리했습니다. 검증 입력 버전은 `question-bound-claims.v2`입니다.

두 모델 합계는 **74/80 통과**입니다. 잘못된 주제의 답변, 전달 미완료와 API 오류는 0건이었고, Luna의 불필요한 보류 6건은 실패로 남겼습니다. Luna에서는 원문에 없는 연도를 추가하거나 인용 문장을 바꿔 무결성 검사에서 차단되는 오류가 남았습니다. 비용이 낮다는 이유로 기본 모델을 Luna로 교체하지 않았습니다.

선택한 Sol 조합은 답변 가능 22/22, 보류 필요 18/18을 통과했습니다. 40회 전체의 p50은 8.71초, p95는 13.24초입니다. 작은 표본의 측정 결과이며 운영 SLO 증거로 사용하지 않습니다.

[별도 질문 파일](../scripts/evals/validation-dataset.ts)은 구현 변경 전에 고정했고, 결과를 본 뒤 질문이나 판정 기준, 평가 대상 에이전트 구현을 조정하지 않았습니다. SHA-256은 `1253741ee1be637d365fb25d1d9002d974a3f35e728ab3df993df47c98e14490`입니다. 다만 같은 공개 합성 근거를 사용하는 표현 및 범위 검증이므로, 새로운 세법 자료에 대한 일반화나 세무 전문가의 독립 평가를 대신하지 않습니다.

추가 80회에는 실제 모델 요청 **326회**가 사용됐으며 사용량 기반 추정 비용은 **$1.48542845**입니다. 초기 평가와 합치면 210회 실행, 모델 요청 821회, 약 **$3.26**입니다. 아래에는 채택하지 않은 초기 후보의 실패와 수정 전후 기록도 남겼습니다.

## 공통 조건과 초기 실험 설계

- 생성 모델: `gpt-5.6-sol`, `gpt-5.6-luna`. 독립 검증 모델은 두 조건 모두 `gpt-5.6-terra`로 고정했습니다.
- 입력: `portfolio-synthetic.v1`의 **8개 질문**. 답변 가능 5개, 근거 없음 1개, 업무 및 조직 범위 밖 2개입니다. 세무 전문가가 정답을 검수한 데이터가 아닙니다.
- 각 조건에서 모델별 2회 반복했습니다. 사전 확인 2회와 본 실험 4조건 × 32회를 합쳐 **130회 실행, 실제 모델 요청 495회**입니다. 고유 질문이 130개라는 뜻은 아닙니다.
- 기본 `current`는 `tax-memo.v1.3.1`, 후보 `grounded`는 `tax-memo.v1.3.2-candidate`입니다. 후보는 원문에 없는 숫자나 문서 제목을 주장에 섞지 않고 검증된 결론을 그대로 전달하도록 지시합니다.
- 모든 실험은 동시 실행 2건, 낮은 추론 강도, Standard 서비스, `store: false`, 같은 독립 검증 모델을 사용했습니다. 프롬프트, 데이터, 코드 파일의 SHA-256과 요청별 응답 ID, 토큰, 시간, 도구 결과를 남겼습니다.

실행 환경은 Node.js 22.21.0, Next.js 16.3.3, AI SDK 7.0.83과 `@ai-sdk/openai` 4.0.52입니다. 각 보고서는 해당 실행 시점의 코드 해시를 보존합니다. 최종 묶음 생성기는 실행 코드와 평가 파일의 일치 여부 및 선택한 불변 프롬프트 해시를 검사합니다. 기본값을 바꾸는 참조 변경과 프롬프트 본문 변경은 구분합니다.

실제 앱의 `ToolLoopAgent`와 세무 도구를 사용하지만 **운영 구성 전체를 통과한 시험은 아닙니다.** OpenAI 직접 연결, 메모리 자료 검색과 로컬 보안 검사 경로입니다. Gateway, PostgreSQL 및 임베딩 검색, 외부 의미 분류기, OIDC, 영구 저장과 검토자 승인 호출은 제외했습니다. 지역 정책의 `synthetic-evaluation` 값도 테스트용 구분자이며 실제 데이터 처리 지역의 증명이 아닙니다.

개별 실행 제한은 진단을 위해 90초로 두었고, 운영의 20초 제한과 누적 토큰 및 비용 예산은 적용하지 않았습니다. 따라서 아래 지연 시간을 운영 SLO 충족 근거로 사용할 수 없습니다. 이 유료 스크립트는 기본 CI에 포함하지 않았습니다.

## 발견한 실패와 조치

### 1. 원문에 없는 연도를 주장에 추가

문서 제목에 있는 연도가 원문 발췌에는 없는데, 모델이 이를 거래 사실 주장에 덧붙였습니다. 숫자 무결성 검사에서 차단된 결과를 정상 답변으로 계산하지 않았습니다. 후보 프롬프트에 본문과 메타데이터의 구분을 명시했고, 기존 검증 기준은 완화하지 않았습니다.

### 2. 서버 안전 안내를 세무 주장으로 오인

서버가 결론에 붙인 “최종 세무 판단과 신고 반영 전 검토자 확인이 필요합니다”라는 안내를 독립 모델이 근거 없는 내부 절차 주장으로 판단했습니다. 후보의 `LEGAL-01`과 `CALC-01` 실행에서는 실제 주장이 모두 `SUPPORTED`인데 이 안내 때문에 전체 답변이 차단됐습니다.

[검증 입력 코드](../src/lib/ai/agents/evidence-verifier.ts)에서 주장 본문과 서버 안내를 분리했습니다. 전체 초안은 여전히 안내를 포함한 정확한 문구 및 산출물 해시와 대조합니다. 실제 모델이 작성한 주장에 같은 문장이 들어 있어도 삭제하거나 검사를 면제하지 않습니다. [계약 테스트](../tests/agent-orchestration.contract.test.ts)에 이 경계, 근거 없는 추가 문장 거부와 최종 안내 유지 검사를 넣었습니다.

### 3. 인용이 정확해도 질문에는 답하지 못함

수정 후 후보는 가업상속공제를 묻는 `ABSENT-01`에 부가가치세 자료를 근거로 답변했습니다. 두 모델에서 각 2회, 총 **4건의 잘못된 응답**입니다. 인용된 원문 자체는 맞더라도 질문에 필요한 근거가 아니므로 모두 실패로 처리했습니다.

따라서 원시 결과의 `unsafeDelivery: false`를 “안전한 정답”으로 읽으면 안 됩니다. 이 필드는 독립 검증과 인용 검사를 건너뛰었는지만 나타냅니다. 별도의 `unexpectedAnswers`와 사례별 통과 여부가 질문 관련성의 실패를 드러냅니다. 이 결과를 이유로 후보를 운영 프롬프트에 등록하지 않았습니다.

기본 Luna의 수정 후 실행에는 검증된 결론을 마지막 전달 단계에서 다시 작성해 바인딩이 거부된 **미완료 3건**도 있습니다. 이를 정상 보류나 API 장애로 섞지 않고 별도 실패로 보존했습니다.

## 초기 실험의 비용과 원시 기록

초기 130회 평가의 사용량 기반 추정 비용은 **$1.7705971**입니다. 생성 모델뿐 아니라 별도 검증 모델 호출도 포함하며, 비용을 알 수 없는 호출은 0건입니다. 별도의 연결 확인 1회는 평가 지표에서 제외했고, 입력 14토큰과 출력 7토큰의 추정 비용은 $0.0000112였습니다. 합계는 약 **$1.77**이며 실제 청구서의 확정 금액은 아닙니다.

[OpenAI 공식 가격표](https://developers.openai.com/api/docs/pricing)의 2026-08-31 Standard 단가를 사용했습니다. 100만 토큰당 입력/출력은 Sol $4/$20, Terra $2/$12, Luna $0.2/$1.2이며 캐시 입력은 별도 단가로 계산합니다. Gateway 가격을 직접 API 호출 비용에 섞지 않았습니다. 단가와 토큰별 계산은 [평가 지표 코드](../scripts/evals/live-metrics.ts)에 있습니다.

[원시 결과 묶음](../artifacts/portfolio/live-evaluation-report.json)의 `experiments`에는 다음 다섯 단계의 원본 보고서가 들어 있습니다. 각 단계의 `report.results`에서 질문, 도구 입력과 출력, 실패 여부, 모델 응답 ID와 비용을 확인할 수 있습니다. 원본 보고서 SHA-256도 함께 보존했습니다. 합성 자료만 포함하며 API 키, 인증 헤더와 모델의 내부 추론은 기록하지 않았습니다.

| 단계              | 목적                                          | 실행 수 |
| ----------------- | --------------------------------------------- | ------: |
| `pilot`           | 기존 경로의 사전 확인, 개선 아이디어의 출발점 |       2 |
| `before-current`  | 기존 프롬프트와 기존 검증 입력                |      32 |
| `before-grounded` | 후보 프롬프트만 변경                          |      32 |
| `after-current`   | 기존 프롬프트, 검증 입력 수정                 |      32 |
| `after-grounded`  | 같은 후보 프롬프트, 같은 검증 입력 수정       |      32 |

질문과 채점 함수의 해시는 모든 단계에서 동일합니다. 기본/후보 프롬프트의 해시도 수정 전후 각각 동일합니다. 실험 중 기본 모델, 검증 모델, 기대 근거와 판정 규칙을 유리하게 바꾸지 않았습니다.

## 재현 방법

저장소에서 `npm ci`를 실행하고, 승인된 `OPENAI_API_KEY`를 Git에서 제외된 `.env.local`에 설정합니다. 최종 설정은 다음과 같이 재평가합니다.

```bash
npm run eval:live -- --variant question-bound
npm run eval:live -- --execute --variant question-bound --dataset development
npm run eval:live -- --execute --variant question-bound --dataset validation
```

첫 명령은 네트워크 요청 없이 계획만 출력합니다. 나머지는 각각 32회와 48회 유료 실행입니다. `--case LEGAL-01 --model gpt-5.6-sol --repetitions 1`로 작은 단위를 지정할 수도 있습니다. 비용 제한을 추가로 설정하는 옵션은 없으며, 실행 횟수와 모델 구성을 확인한 뒤 명시적으로 실행해야 합니다.

비교용 `current`는 이름과 달리 과거 기본값인 `tax-memo.v1.3.1`을 가리키고, `grounded`는 채택하지 않은 1.3.2 후보입니다. 인수 없는 `eval:live`도 과거 기준의 계획을 출력하므로 최종 설정을 측정할 때는 `--variant question-bound`를 사용합니다.

결과는 매번 `artifacts/portfolio/live-evals/<실행 시각>/report.json`에 새로 저장됩니다. 인증이나 할당량 오류가 나면 새 호출을 중단하고 이미 끝난 결과를 덮어쓰지 않습니다. 현재 스크립트는 실행 미완료 시 종료 코드 2, 완료했어도 품질 실패가 있으면 1을 반환합니다. 과거 스크립트의 종료 코드 0은 품질 통과를 뜻하지 않았습니다.

최종 묶음은 다음 명령으로 생성합니다. 원본 파일 경로는 해당 실행 결과로 지정합니다.

```bash
node --conditions=react-server --import tsx scripts/portfolio/build-release-report.ts \
  --development artifacts/portfolio/live-evals/<개발 실행 시각>/report.json \
  --validation artifacts/portfolio/live-evals/<검증 실행 시각>/report.json
```

[최종 보고서 생성기](../scripts/portfolio/build-release-report.ts)는 누락 및 중복 사례, 중복 모델 응답 ID, 질문 변경, 코드 해시와 채점 결과를 확인합니다. 선택한 Sol의 두 세트가 모두 통과해야 `promotionGate.passed`가 참입니다. 비교 모델의 실패는 삭제하지 않습니다. 보고서를 합치는 과정에서는 모델을 호출하지 않습니다.

[초기 보고서 생성기](../scripts/portfolio/build-live-report.ts)는 과거 다섯 단계의 원본 보존용으로 남겨 뒀습니다. 현재 코드로 과거 프롬프트를 실행하더라도 그 당시 오케스트레이션이나 확률적 출력이 그대로 재현되는 것은 아닙니다.

## 채택 판단과 남은 일

**적용한 것:** 원래 질문에 묶인 검색과 독립 검증, 서버 보관 검증본 전달, 실패 시 명시적 보류, 경계 회귀 테스트와 `tax-memo.v1.4.0` 기본 선택입니다. 생성 모델은 기존 Sol을 유지했습니다. 공개 데모는 유료 AI 모드로 전환하지 않았습니다.

**채택하지 않은 것:** 1.3.2 후보와 Luna로의 모델 교체입니다. Luna는 추가 실험에서도 불필요한 보류가 남았으며, 저렴하다는 이유로 이 품질 차이를 무시하지 않았습니다.

실사용 전에는 세무 전문가가 검수한 정답과 새로운 세목, 기간, 예외 규정을 포함한 독립 세트가 필요합니다. 실제 Gateway와 PostgreSQL 검색, 인증 및 승인 서비스를 연결한 동일 환경에서 한국어 표현 변형, 프롬프트 인젝션, 품질, 지연 시간과 비용을 다시 검증해야 합니다. 이번 합성 질문의 통과만으로 세무 결론을 자동 확정하거나 실고객 데이터를 처리하지 않습니다.
