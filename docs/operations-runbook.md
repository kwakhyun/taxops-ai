# 운영 런북

## 배포 전 확인

1. `npm ci` 후 `npm run verify`와 `npm run test:e2e`를 통과합니다.
2. 마이그레이션을 스테이징 복제 환경에 적용하고 RLS의 허용·차단 사례를 확인합니다.
3. 커밋 SHA로 웹, 워커와 검토 서비스 이미지를 만들고 변경 불가능한 태그와 다이제스트를 기록합니다.
4. Terraform 실행 계획을 클라우드·보안 담당자가 검토합니다.
5. OIDC 클라이언트와 세션 비밀값, DB 역할별 URL, AI 키, 승인 비밀값, 개인정보 비식별화·의미 분류·문서 처리 토큰, 알림 HMAC 비밀값을 Secrets Manager에서 주입합니다.
6. `/api/health/ready`의 상태 코드가 정상인지 확인합니다. 의존 서비스별 진단은 `HEALTH_DETAIL_TOKEN`을 Bearer 토큰으로 전달한 내부 운영 요청에서만 확인합니다. 워커 시작 로그에서는 DB, S3와 ClamAV 연결 검사 성공을 확인합니다.
7. `AI_PROMPT_VERSION`이 코드에 등록된 버전이고 평가 보고서의 `promptVersion`·`promptHash`와 일치하는지 확인합니다. 새 프롬프트나 모델은 세무 검토자의 승인 기록과 함께 배포 변경에 첨부합니다.
8. `TAXOPS_LOCAL_STACK`이 운영 작업 정의에 없고, 실제 의미 분류기의 호스트, 처리 지역, 임계값과 승인된 `modelVersion`이 스테이징 평가 기록과 일치하는지 확인합니다.
9. 전체 감사 체인 검증 건수와 최종 해시를 외부 WORM 저장소의 최근 서명 기준점과 대조합니다.

## 주요 대시보드

- HTTP: 요청 수, 상태 코드, p50/p95/p99와 경로별 오류율
- AI: 모델·프롬프트·검색 버전별 지연 시간, 토큰, 비용, 답변 보류와 검증 에이전트 반려율
- 검색: 검색 결과 수, 점수 분포, 표본 Recall과 인용 수
- 워커: 큐 깊이, 가장 오래 대기한 시간, 임대 만료, 재시도, DLQ와 파서·ClamAV 오류
- 알림: `outbox_events` 대기 수, 임대 소유자와 만료 시각, 전송 시도, 10회 실패 이벤트와 웹훅 응답 코드
- 보안: OIDC 실패, RBAC 거부, 조직 불일치, 승인 재사용과 MCP 호스트·Origin 거부
- 데이터: DB 연결, 느린 쿼리, 저장소 증가량, 백업과 복구 상태

로그에는 요청 ID, 추적 ID, 행위자 ID, 조직 ID, 대상 ID와 결과 코드만 허용하며 파일 내용, 질문, 답변, 이메일과 액세스 토큰은 남기지 않습니다.

## 장애 대응

### 조직 간 정보 노출 의심

AI와 MCP 트래픽을 즉시 차단하고 P0 사고를 선언합니다. 관련 추적 ID, 배포 다이제스트와 DB 감사 체인을 보존한 뒤 RLS와 저장소 필터를 확인합니다. 원문을 일반 로그에 복사하지 않습니다. 영향을 받은 조직과 법적 통지 여부는 보안·개인정보 담당자가 판단합니다.

### AI 근거 오류 증가

현재 모델, 프롬프트와 검색 버전의 배포를 중단합니다. 이전 검증 버전으로 되돌리고 실패 질문을 비식별 기준 평가 세트에 추가합니다. 검색 실패, 도구 계산과 검증 에이전트 누락을 단계별로 분리해 조사합니다.

### 문서 작업 정체

가장 오래 대기한 작업, 임대 소유자와 만료 시각, ClamAV, 문서 처리기, S3와 DB 상태를 확인합니다. 임대가 만료되면 다른 워커가 자동으로 다시 임대합니다. 영구 실패는 원인 수정 후 새 멱등성 키로 명시적으로 재처리하고 원래 감사 기록은 유지합니다.

### 알림 전송 정체

`outbox_events`의 `available_at`, `lease_owner`, `lease_expires_at`, `attempts`, `last_error_code`를 확인합니다. 워커는 웹훅 제한 시간보다 긴 임대를 획득한 뒤 멱등성 키와 HMAC 서명을 포함해 HTTPS 웹훅을 호출합니다. 실패하면 임대를 해제하고 지수 재시도를 예약합니다. 10회를 소진한 이벤트는 원인을 해결한 뒤 새 멱등성 키로 다시 발행합니다.

### 객체 저장소·DB 장애

새 업로드와 쓰기 기능을 중단하고 읽기 범위를 최소화합니다. RDS 시점 복구와 S3 버전을 별도 복구 환경에서 검증합니다. 감사 체인 연속성과 객체 체크섬을 확인한 뒤 서비스를 재개합니다.

### 의미 분류기 장애 또는 보안 재스캔

분류기 시간 초과, 응답 스키마 불일치와 처리 지역 불일치가 발생하면 오류 시 차단 원칙에 따라 자료 인덱싱을 중단합니다. 대체 모델로 자동 우회하지 말고 승인된 `modelVersion`을 복구합니다.

분류 정책 변경 마이그레이션이 기존 `INDEXED` 자료를 `QUARANTINED`로 되돌리면 변경 불가능한 객체 연결 정보가 있는 자료만 재처리합니다. 연결 정보가 없는 자료는 `FAILED` 보정 이벤트로 조사합니다. 관련 근거가 다시 `SAFE`, `INDEXED`, `APPROVED`가 되기 전에는 연결된 승인 대기 검토조서를 승인하지 않습니다.

### 공식 세무 원천 또는 감사 기준점 불일치

공식 원천의 발행기관, HTTPS URI와 수집 시각만으로 진위를 확정하지 않습니다. 연계 서비스가 검증한 서명 또는 승인된 다이제스트와 맞지 않으면 `TAX_AUTHORITY` 자료를 검색에서 제외하고 보안 담당자와 세무 지식 관리자가 다시 수집합니다.

DB 전체 감사 체인은 변조 탐지 통제입니다. 외부 WORM 기준점이 없거나 최종 해시가 다르면 쓰기 기능을 중단하고 별도 복구 환경에서 조사합니다.

## 롤백

- 애플리케이션: 웹, 워커와 검토 서비스의 이전 이미지 다이제스트로 ECS 작업 정의를 되돌립니다.
- 프롬프트: `AI_PROMPT_VERSION`을 코드에 등록된 이전 버전으로 바꾸고 `npm run eval`에서 동일한 버전과 해시가 기록되는지 확인한 뒤 배포합니다. 등록되지 않은 값은 준비 상태 검사에서 503으로 거부됩니다.
- 모델: `AI_MODEL_ID`와 `AI_VERIFIER_MODEL_ID`를 이전 검증값으로 되돌리고 같은 프롬프트로 평가를 다시 실행합니다.
- DB: 확장·축소 마이그레이션을 원칙으로 합니다. 파괴적인 하향 마이그레이션 대신 이전 앱이 읽을 수 있는 호환 상태를 유지합니다.
- 문서 인덱스: `document_version`으로 이전 청크를 보존하고 검증된 버전만 다시 `is_current = true`로 전환합니다.
