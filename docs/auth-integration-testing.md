# 실제 OIDC 인증 연동 검증

`npm run test:auth-e2e`는 공개 데모와 별개로 테스트 인증기관, PostgreSQL, 검토 서비스와 웹 서버를 실행합니다. 브라우저의 인증 요청을 가로채거나 토큰 응답을 대체하지 않습니다. 기존 `tests/e2e/auth-recovery.spec.ts`는 오류 응답을 주입해 복구 화면을 검사하고, 이 테스트는 실제 프로토콜과 DB 경계를 검사합니다.

## 테스트 환경

- 인증기관: [oidc-provider](https://github.com/panva/node-oidc-provider) 9.12.2. Authorization Code, PKCE S256, JWKS, 서명된 ID 토큰과 검토 서비스용 Access Token을 사용합니다.
- 인증 수단: 실행마다 생성한 테스트 계정 비밀번호와 [OTPAuth](https://github.com/hectorm/otpauth)의 30초 TOTP입니다. 이미 사용한 인증번호는 다시 허용하지 않습니다.
- 데이터베이스: PostgreSQL 16과 pgvector. 기존 마이그레이션과 합성 데이터를 적용하고 웹, 검토 서비스에 각각 제한된 DB 역할을 연결합니다.
- 데이터 수명: 인증기관 상태와 키는 메모리에만 보관합니다. DB도 실행별 이름의 컨테이너와 임시 메모리 파일시스템을 사용하며 종료 시 제거합니다. 기존 DB와 운영 환경변수는 수정하지 않습니다.

## 실행

Node.js 22 이상, Docker 또는 Docker와 연결된 Colima, Docker Compose, Playwright Chromium이 필요합니다.

```sh
npm ci
npx playwright install chromium
npm run test:auth-e2e
```

macOS에서 별도 Colima 프로필을 사용할 경우 먼저 해당 Docker context를 선택한 환경에서 명령을 실행합니다. 실행 도구 자체는 VM을 시작하거나 다른 프로젝트의 컨테이너를 종료하지 않습니다.

다음 포트는 비어 있어야 합니다. 모든 서비스는 `127.0.0.1`에만 연결합니다.

| 서비스          | 포트  |
| --------------- | ----- |
| 웹              | 3218  |
| 테스트 인증기관 | 3219  |
| 검토 서비스     | 3220  |
| 임시 PostgreSQL | 55437 |

검증은 브라우저 작업자 1개로 순차 실행합니다. 웹 프로세스의 V8 힙은 1.5GB, 검토 서비스는 384MB로 제한합니다. 이는 전체 프로세스 메모리의 상한은 아닙니다. DB 컨테이너는 384MB와 0.75 CPU로 제한하며, macOS 부하 평균이 CPU 수의 2배를 초과하면 시작하지 않습니다. 부하가 낮더라도 다른 작업이 메모리를 많이 사용하고 있다면 먼저 정리해야 합니다.

## 확인하는 경계

1. 인증기관의 discovery, 공개 JWKS, PKCE 지원과 잘못된 토큰 요청 거부
2. 잘못된 비밀번호와 OTP 거부, 정상 로그인 후 업무 화면 복귀
3. DB 소속이 없는 사용자 거부와 역할별 API 접근 제한
4. 로그아웃 시 DB 세션 폐기와 이전 쿠키 재사용 차단
5. 실제 인증 화면에서 취소한 경우의 안내 화면과 임시 쿠키 정리
6. 재인증 중 다른 계정으로 전환하는 요청 거부
7. 검토자 쿠키 만료 후 새 탭에서 재인증, 원래 검토 의견 유지, 명시적 재시도 후 승인 저장

결과는 Git에서 제외한 `artifacts/auth-test/results.json`과 `artifacts/auth-test/verification.json`에 남습니다. 인증 비밀번호, OTP 비밀값과 토큰은 결과에 저장하지 않습니다. 인증 테스트에서는 화면 녹화, 스크린샷과 네트워크 추적을 사용하지 않습니다.

## 검증 범위의 한계

이는 독립적으로 실행한 실제 OIDC 서버와 애플리케이션의 통합 검증입니다. Auth0, Microsoft Entra ID 등 특정 조직의 인증기관 설정을 검증한 것은 아닙니다. 테스트 인증기관의 계정 관리와 사전 동의 정책은 합성 데이터 검증에 한정되며 운영용으로 배포하면 안 됩니다.

로컬 개발 모드의 HTTP만 사용합니다. 실제 서비스 전에는 운영 TLS, 인증기관별 클레임 매핑, 사용자 등록과 조직 소속 동기화, MFA 등록·복구 정책, 인증기관 장애 대응을 해당 조직 환경에서 별도로 검증해야 합니다. 검토자 쿠키 만료 시나리오는 브라우저 쿠키를 만료시켜 실행하며, 15분 경과한 토큰과 오래된 `auth_time`의 거부는 별도 JWT 회귀 테스트에서 검증합니다.
